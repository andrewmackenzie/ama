# Installomator support for Ama

Ama ships with everything needed to be installed and kept up to date by
[Installomator](https://github.com/Installomator/Installomator) and the MDM/patch tools built
on it. Two pieces, both depending only on tools already on every Mac (`curl` + `xmllint`):

- **The appcast** — `ama.xml`, a small Sparkle-format XML that advertises the latest version
  and the exact package URL. Generated by `build-pkg.sh`; you host it.
- **The label / updater** — `installomator/ama.sh` (a case-block label) or
  `scripts/installomator/update-ama.sh` (a self-contained `valuesfromarguments` updater for
  MDM, no Installomator rebuild required).

## How the version check works

1. Installomator reads the installed version from `/Applications/Ama.app`
   (`CFBundleShortVersionString`).
2. It curls the appcast and parses two values with `xmllint`:
   - `appNewVersion` ← `//item[1]/title`
   - `downloadURL`   ← `//item[1]/enclosure/@url`
3. If installed == `appNewVersion`, it stops. Otherwise it downloads the pkg, verifies it was
   signed by Team `674T5RS44U`, quits Ama, and installs.

The pkg URL is stable (always the latest); the appcast carries the version, so Installomator
only downloads when the installed version differs.

## Using the built-in label

Drop `installomator/ama.sh` into your Installomator label set (`fragments/labels/ama.sh`)
and rebuild `Installomator.sh`, or paste the case block into your MDM/patch tool's custom
labels. Then: `./Installomator.sh ama`.

## Without rebuilding Installomator: `valuesfromarguments`

`scripts/installomator/update-ama.sh` reads the appcast, self-installs Installomator if
needed, and runs the built-in `valuesfromarguments` label. Deploy it as an MDM script/policy;
it no-ops when Ama is absent or already current. The core call:

```sh
FEED="https://www.capstannetworks.com/ama/ama.xml"
AMA_FEED=$(curl -fsL "$FEED")
appNewVersion=$(echo "$AMA_FEED" | xmllint --xpath 'string(//item[1]/title)' - 2>/dev/null)
downloadURL=$(echo "$AMA_FEED" | xmllint --xpath 'string(//item[1]/enclosure/@url)' - 2>/dev/null)

sudo /usr/local/Installomator/Installomator.sh valuesfromarguments \
  name="Ama" \
  type="pkg" \
  downloadURL="$downloadURL" \
  appNewVersion="$appNewVersion" \
  expectedTeamID="674T5RS44U" \
  blockingProcesses="Ama"
```

Ama's name and process have no spaces, so no shell-quoting gymnastics are needed. Prefix
with `DEBUG=1` (and drop `sudo`) for a dry run.

## Where the files come from

`./build-pkg.sh` produces both `Ama.pkg` (notarized, stapled, stable name) and `ama.xml`
(appcast) in `build/dist/`. `./release.sh` publishes them to a GitHub release; the website
serves them at `https://www.capstannetworks.com/ama/`. The appcast's `<enclosure url>` must
match wherever the website serves the pkg. This is a real Sparkle appcast — if Ama later
wires up in-app auto-update with Sparkle, it reads this same file.
